# Feature Specification: 能登半島DEM断面図WebGIS(DEM Cross-Section Viewer)

**Feature Branch**: `001-dem-cross-section`

**Created**: 2026-08-08

**Status**: Draft

**Input**: User description: "idea.mdの内容を元に、能登半島北部を対象としたDEM断面図WebGISサービスの機能仕様を作成してください。憲法(.specify/memory/constitution.md)の制約(静的サイト/GitHub Pages, Leaflet, COG/EPSG:6675/0.5m解像度, PNGダウンロード等)を踏まえること。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 任意の測線でDEM断面図を作成する (Priority: P1)

ユーザーは地図上で任意の2点(始点・終点)を指定し、サンプリング間隔を指定することで、その測線に沿った地形断面図(横軸: 始点からの距離、縦軸: 標高)を表示できる。

**Why this priority**: これが本サービスの中核価値であり、これ単体でも「任意地点の断面図が見られる」という最小限の価値を提供できるMVP。

**Independent Test**: 地図上で2点をクリックして測線を指定し、サンプリング間隔を入力した状態で、距離-標高グラフが画面に表示されることを確認する。

**Acceptance Scenarios**:

1. **Given** 地図画面が表示されている、**When** ユーザーが地図上で始点・終点をクリックして測線を指定する、**Then** 指定した測線が地図上に描画される。
2. **Given** 測線が指定されている、**When** ユーザーがサンプリング間隔(メートル)を入力して断面図の作成を実行する、**Then** 始点からの距離(d)と標高(z)からなる断面図が表示される。
3. **Given** 断面図が表示されている、**When** ユーザーが測線を引き直す、**Then** 断面図は新しい測線の内容に更新される。

---

### User Story 2 - 複数時期のDEMを重ねて地形変化を比較する (Priority: P2)

ユーザーは同一の測線について、地震前・地震後・豪雨後など複数時期のDEMそれぞれの断面図を1つのグラフ上に重ねて表示し、地形変化(隆起・沈降・侵食・堆積など)を比較できる。

**Why this priority**: 「複数時期の地形変化を捉える」ことが能登半島北部を対象とする本質的な目的であり、単一時期の断面図(P1)だけでは提供できない価値。

**Independent Test**: 複数時期のDEMが設定された状態で断面図を作成し、時期ごとに視覚的に区別された(色分けなどの)複数の線が同一グラフ上に表示されることを確認する。

**Acceptance Scenarios**:

1. **Given** 複数時期のDEMデータセットが利用可能である、**When** ユーザーが断面図を作成する、**Then** 各時期のDEMに基づく断面線が同一グラフ上に色分け等で表示される。
2. **Given** 複数時期の断面図が表示されている、**When** ユーザーがグラフを確認する、**Then** どの線がどの時期のDEMに対応するかを示す凡例が表示される。

---

### User Story 3 - 断面図をPNGでダウンロードする (Priority: P2)

ユーザーは作成した断面図をPNG形式のファイルとしてダウンロードし、レポートや資料に利用できる。

**Why this priority**: 断面図を「見る」だけでなく「持ち出して使う」ことができて初めて実務的な価値になるため、P1・P2に次いで重要。

**Independent Test**: 断面図が表示された状態でダウンロード操作を行い、PNGファイルがローカルに保存され、画像として開けることを確認する。

**Acceptance Scenarios**:

1. **Given** 断面図が表示されている、**When** ユーザーがダウンロード操作を行う、**Then** 表示内容と一致するPNGファイルがダウンロードされる。

---

### User Story 4 - 測線をオーバーレイした地図をPNGでダウンロードする (Priority: P3)

ユーザーは断面図の作成に使用した測線を地図上にオーバーレイした状態で、縮尺表示付きの地図画像をPNG形式でダウンロードできる。

**Why this priority**: 断面図単体よりも「どこの断面か」を示す地図があることで資料としての価値が高まるが、断面図そのもの(P1-P3)が先に成立している必要がある。

**Independent Test**: 測線が描画された地図状態でダウンロード操作を行い、測線と縮尺表示を含むPNGファイルが得られることを確認する。

**Acceptance Scenarios**:

1. **Given** 測線が地図上に描画されている、**When** ユーザーが地図のダウンロード操作を行う、**Then** 測線と縮尺(スケールバー)を含む地図PNGファイルがダウンロードされる。

---

### User Story 5 - 対象地域のタイル地図を背景表示する (Priority: P4)

開発者/運用者があらかじめ指定した複数のタイル地図(例: 時期の異なるオルソ画像、CS立体図、赤色立体図)の中から、ユーザーが地図画面上のレイヤー切替コントロールで背景を選んで表示できる。

**Why this priority**: 背景地図はコンテキストを提供する補助的機能であり、断面図生成というコア機能(P1-P3)がなくても地図表示自体は成立するため優先度は最も低い。

**Independent Test**: 運用者が設定した複数のタイル候補が、地図画面のレイヤー切替コントロールから選択でき、選択したタイル画像が背景として表示されることを確認する。

**Acceptance Scenarios**:

1. **Given** 運用者があらかじめ複数のタイル配信アドレスを設定済みである、**When** ユーザーが地図画面を開く、**Then** 既定のタイル画像が地図の背景として表示される。
2. **Given** 地図画面が表示されている、**When** ユーザーがレイヤー切替コントロールで別のタイルを選択する、**Then** 地図の背景が選択したタイル画像に切り替わり、出典表示も切り替わる。

---

### Edge Cases

- 測線の一部または全部が、利用可能なDEMのデータ範囲外にある場合、断面図はその区間をデータ欠損として明示する(補間や外挿は行わない)。
- 測線の始点と終点が同一地点(距離ゼロ)の場合、システムはエラーメッセージを表示し断面図を生成しない。
- サンプリング間隔がDEMの解像度(0.5m)より小さい値で指定された場合、隣接するDEM画素値から補間して標高を算出する。
- 複数時期のDEMのうち、一部の時期でその測線区間のデータが存在しない(欠測)場合、その時期の線はその区間のみ途切れた状態で表示される。
- 測線長が10kmを超える、または算出される総サンプル点数が20,000点を超える場合、システムは処理を実行する前に想定サンプル点数を提示し、ユーザーに続行可否を確認する(具体的な閾値は運用状況に応じて調整可能な既定値とする)。
- 指定されたタイル配信アドレスが無効・到達不能な場合、地図の該当領域は空白または既定のフォールバック表示となり、断面図生成機能自体は継続して利用できる。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: システムは地図画面上に、運用者があらかじめ設定した複数のタイル配信候補の中から既定のものを背景地図として表示しなければならない。
- **FR-002**: ユーザーは地図上の操作(クリック等)により、測線の始点・終点をWGS84の緯度経度座標として指定できなければならない。
- **FR-003**: システムは指定された始点・終点の座標をEPSG:6675(メートル単位の平面直角座標系)に変換しなければならない。
- **FR-004**: ユーザーは測線上のDEMサンプリング間隔をメートル単位で指定できなければならない。
- **FR-005**: システムは測線とサンプリング間隔から、各サンプリング点における「始点からの距離(d)」と「DEMから取得した標高(z)」の配列を生成しなければならない。
- **FR-006**: システムは、あらかじめ用意された複数時期(能登半島北部における2024年1月の地震・2024年9月の豪雨の前後を含む)のDEM(COG形式)それぞれについて、同一の測線上でd, z配列を生成しなければならない。
- **FR-007**: システムは複数時期のd, z配列を、時期ごとに視覚的に区別可能な形で1つの断面図(距離-標高グラフ)上に重ねて表示しなければならない。
- **FR-008**: 断面図には、どの線がどの時期のDEMに対応するかを示す凡例を表示しなければならない。
- **FR-009**: ユーザーは表示された断面図をPNG形式のファイルとしてダウンロードできなければならない。
- **FR-010**: システムは測線を地図上にオーバーレイして描画し、地図画面には縮尺(スケールバー)を表示しなければならない。
- **FR-011**: ユーザーは測線をオーバーレイした地図をPNG形式のファイルとしてダウンロードできなければならない。
- **FR-012**: システムは測線がDEMのデータ提供範囲外に出る区間を検出し、断面図上でデータ欠損として明示しなければならない。
- **FR-013**: システムはサーバーサイドの実行環境を必要とせず、静的ファイルの配信のみで動作しなければならない(ブラウザ内で座標変換・DEMサンプリング・断面図生成を完結させる)。
- **FR-014**: ユーザーは断面図上で、表示する各DEM時期の線を個別に表示/非表示切り替えできなければならない。
- **FR-015**: タイル配信アドレス(URLテンプレート)の候補一覧は開発者/運用者があらかじめ設定するものとし、任意のURLをエンドユーザーが自由入力できるUIは提供しない。ユーザーは、あらかじめ用意された候補の中からレイヤー切替コントロールで選択できる(FR-016)。
- **FR-016**: ユーザーは、運用者があらかじめ設定した複数の背景タイル候補の中から、地図画面上のレイヤー切替コントロールで表示するタイルを選択できなければならない。

### Key Entities *(include if feature involves data)*

- **測線 (Transect Line)**: ユーザーが指定する始点・終点(WGS84緯度経度およびEPSG:6675変換後座標)とサンプリング間隔を持つ。断面図・地図オーバーレイの入力となる。
- **DEMデータセット (DEM Dataset)**: 取得時期のラベル(例: 地震前/地震後/豪雨後)、COGファイルへの参照、空間参照系(EPSG:6675)、解像度(0.5m)を持つ。複数存在し得る。
- **断面プロファイル点 (Profile Point)**: 測線上のサンプリング位置ごとに、始点からの距離(d)と、各DEMデータセットにおける標高(z、欠損の場合あり)を持つ。
- **断面図 (Cross-Section Profile)**: 測線と、複数DEMデータセットに対応するプロファイル点配列の集合。画面表示およびPNG出力の対象。
- **タイルレイヤー設定 (Tile Layer Config)**: 背景地図として参照するタイル配信の候補一覧。それぞれ識別子・表示ラベル・URLテンプレート・出典表記を持つ。複数存在し得る(FR-016)。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: ユーザーが地図上で測線とサンプリング間隔を指定してから10秒以内に断面図が表示される。
- **SC-002**: ユーザーは追加のソフトウェアインストールや専門的なGISツールなしに、Webブラウザのみで「測線指定 → 断面図確認 → PNGダウンロード」の一連の作業を完了できる。
- **SC-003**: 初めて本サービスを使うユーザーの90%が、説明なしで測線を指定し断面図を表示するところまでのタスクを完了できる。
- **SC-004**: ダウンロードされた断面図PNGおよび地図PNGは、軸ラベル・凡例・縮尺表示が判読可能な品質で、印刷や報告資料にそのまま利用できる。
- **SC-005**: 複数時期のDEMを重ねた断面図により、ユーザーは地震・豪雨前後で標高が変化した区間(隆起・沈降・侵食・堆積等)を目視で識別できる。

## Assumptions

- 対象範囲外(タイル・DEMともにデータが存在しない領域)は、地図上は空白またはフォールバック表示、断面図上はデータ欠損として扱う。
- DEMのCOGファイルおよび背景タイルは、いずれも外部または同一リポジトリ内の静的ファイルとしてWeb上に既に配置されている前提とし、本サービスはそれらを参照して読み込むのみで、データ作成・変換・ホスティングは行わない。
- 標準搭載する複数時期のDEMは「地震前」「地震後(地震直後〜豪雨前)」「豪雨後」の3時期を基本構成と仮定する。具体的な取得日・ファイル一覧は実データ準備時に確定する。
- ユーザーはPC/デスクトップの一般的なモダンブラウザとインターネット接続を持つ。モバイル端末での操作性最適化は本バージョンのスコープ外とする。
- 認証・アクセス制御は不要(公開データを扱うオープンな閲覧サービスとして提供する)。
- 同時アクセスユーザー数についての特別な性能要件はない(静的サイト配信のため、スケーラビリティはホスティング基盤に依存する)。
- 測線長10km・サンプル点数20,000点という確認プロンプトの閾値は初期既定値であり、実データでの検証結果に応じて調整してよい。
