# Feature Specification: 測線Shapefileダウンロード

**Feature Branch**: `004-transect-shapefile-export`

**Created**: 2026-09-07

**Status**: Draft

**Input**: User description: "測線の位置情報をShapefile形式でもダウンロードできるボタンを追加する。既存のKMLダウンロード機能と同様に、地図上で指定した測線(始点・終点)の位置情報を、QGISやArcGISなど他のGISソフトウェアで直接開けるESRI Shapefile形式(.shp/.shx/.dbf/.prj一式をまとめたzip)としてダウンロードできるようにする。座標系はKML同様WGS84(緯度経度)とする。ジオメトリは測線を表す1本のポリライン(始点→終点)とする。既存のKMLダウンロードボタンの隣に「測線をShapefileでダウンロード」ボタンを追加し、断面図生成前でも測線が指定されていればダウンロードできるようにする(KMLダウンロードボタンと同じ有効化条件)。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 測線をShapefileでダウンロードしてGISソフトで開く (Priority: P1)

ユーザーは地図上で測線(始点・終点)を指定した後、「測線をShapefileでダウンロード」ボタンを押すと、測線を1本のポリライン(始点→終点)として含むESRI Shapefile一式(.shp/.shx/.dbf/.prj)をまとめたzipファイルがダウンロードされる。ユーザーはこのzipをQGISやArcGISなどのGISソフトウェアにそのまま読み込み、他の空間データと重ね合わせて確認できる。

**Why this priority**: 本機能の核心的価値そのもの。これがなければ機能として成立しない。

**Independent Test**: 地図上で測線を指定し、「測線をShapefileでダウンロード」ボタンを押してzipファイルを取得する。zipを展開し、GISソフトウェア(またはShapefileを検証できるツール)で開いて、始点・終点を結ぶ1本の線が正しい位置(指定した緯度経度)に表示されることを確認する。

**Acceptance Scenarios**:

1. **Given** 地図上で測線(始点・終点)が指定されている、**When** ユーザーが「測線をShapefileでダウンロード」ボタンを押す、**Then** `.shp`・`.shx`・`.dbf`・`.prj`の4ファイルを含むzipファイルがダウンロードされる。
2. **Given** ダウンロードしたzipをGISソフトウェアで開く、**When** レイヤーを表示する、**Then** 測線の始点・終点を結ぶ1本のポリラインが、指定した緯度経度と一致する位置に表示される。
3. **Given** 測線を指定したが断面図をまだ作成していない、**When** ユーザーが「測線をShapefileでダウンロード」ボタンを押す、**Then** 断面図の作成有無に関わらずダウンロードが成功する(既存のKMLダウンロードと同じ条件)。

---

### User Story 2 - 測線が未指定の間はダウンロードできないことが分かる (Priority: P2)

ユーザーが地図上でまだ測線を指定していない間は、「測線をShapefileでダウンロード」ボタンは無効化されており、誤操作でダウンロードを試みることがない。

**Why this priority**: 誤操作防止のための補助的な振る舞いであり、既存のKML・地図PNGダウンロードボタンと一貫した挙動にするため。P1がなくても機能の核心的価値は損なわれない。

**Independent Test**: 測線を指定する前にボタンが無効化されていること、測線を指定すると有効化されることを確認する。

**Acceptance Scenarios**:

1. **Given** 地図上で測線がまだ指定されていない、**When** 画面を確認する、**Then** 「測線をShapefileでダウンロード」ボタンは無効化されている。
2. **Given** ボタンが無効化されている、**When** ユーザーが地図上で測線(始点・終点)を指定する、**Then** ボタンが有効化される。

### Edge Cases

- 測線の始点と終点が地図上で非常に近い(距離がほぼゼロ)場合: 通常のポリラインとしてそのまま出力する(既存のKML出力と同様、特別なエラー処理は行わない)。
- 同名のzipファイルが既にダウンロード先に存在する場合: ブラウザ標準のファイル名重複時の挙動(自動リネーム等)に従う(アプリ側で特別な制御は行わない)。
- Shapefile形式では1レイヤーにつき1つの属性テーブル(.dbf)を持つため、属性値には測線名など日本語を含まないASCII文字のみを格納し、文字化けを防ぐ。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: システムは、地図上で測線(始点・終点)が指定されている場合に、その測線をESRI Shapefile形式でダウンロードできるボタンを提供しなければならない。
- **FR-002**: システムは、測線を1本のポリライン(始点→終点)のジオメトリとして、緯度経度(WGS84)の座標系でShapefileに出力しなければならない。
- **FR-003**: システムは、Shapefile出力に必要な構成ファイル(`.shp`・`.shx`・`.dbf`・`.prj`)一式を1つのzipファイルにまとめてダウンロード提供しなければならない。
- **FR-004**: システムは、断面図の作成有無に関わらず、測線が指定されていればShapefileダウンロードを実行できなければならない(既存のKMLダウンロードボタンと同じ有効化条件)。
- **FR-005**: システムは、測線が指定されていない間、Shapefileダウンロードボタンを無効化しなければならない。
- **FR-006**: システムが出力するShapefileは、一般的なGISソフトウェア(QGIS・ArcGIS等)で座標のずれや破損なく読み込める形式でなければならない。

### Key Entities

- **測線Shapefileエクスポート**: 既存の測線(始点・終点の緯度経度)を入力として、ポリライン1本分のジオメトリと最小限の属性(測線名など)を持つShapefile一式(.shp/.shx/.dbf/.prj)を生成し、zipにまとめたもの。既存のKMLエクスポートと同じ入力データ(測線の始点・終点)を、異なる出力形式に変換したものであり、新たな入力データは必要としない。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: ユーザーは測線を指定した後、追加の設定操作なしにワンクリックでShapefile(zip)をダウンロードできる。
- **SC-002**: ダウンロードしたShapefileをGISソフトウェアで開いたとき、指定した測線の始点・終点の緯度経度と、表示されるポリラインの位置のずれが実用上ないことを確認できる(座標変換・エンコードの誤りがない)。
- **SC-003**: 断面図を作成しているかどうかに関わらず、測線さえ指定されていれば100%の操作でダウンロードに成功する。

## Assumptions

- Shapefile出力のジオメトリは測線(始点→終点の1本のポリライン)のみとし、既存のKML出力に含まれる始点・終点の個別ポイント(Placemark)に相当するものは、Shapefileでは別ジオメトリ型となり1ファイルに混在できないため、本機能の対象外とする。
- Shapefileの属性テーブル(.dbf)に格納する属性は最小限(測線名などのASCII文字列)とし、文字コードの都合上、日本語などの多バイト文字はそのままでは格納しない。
- 座標系はKML出力と同様、WGS84(緯度経度、EPSG:4326)を用いる。DEMサンプリングに用いるEPSG:6675への変換は行わない。
- ダウンロードボタンの配置・有効化条件は、既存の「測線をKMLでダウンロード」ボタンと同じUIパターン(測線指定時のみ有効)を踏襲する。
