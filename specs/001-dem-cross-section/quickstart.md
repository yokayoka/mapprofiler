# Quickstart: 動作確認ガイド

このガイドは、実装後に本機能がエンドツーエンドで動作することを手動で検証するための手順である。
実装コード自体はここに含めない(詳細は `data-model.md` / `contracts/` を参照)。

## 前提条件

- Node.js(LTS)がインストールされていること。
- `src/config/datasets.ts`(`contracts/config-schema.md` 参照)に、実データまたはテスト用の
  DEM COGファイル(EPSG:6675、HTTP Range Request + CORS対応の配信元)を1件以上設定していること。
- `tileLayerConfig` に、CORSを許可するタイル配信アドレスを設定していること(未設定でも
  User Story 1〜3の断面図生成自体は確認可能。地図PNGダウンロード確認にはCORS対応が必要)。

## セットアップ

```bash
npm install
npm run dev
```

ブラウザで表示された開発サーバーのURL(例: `http://localhost:5173`)を開く。

## シナリオ1: 単一測線の断面図作成(User Story 1)

1. 地図画面が表示され、対象地域(能登半島北部)周辺が背景地図とともに表示されることを確認する。
2. 地図上をクリックして始点を指定し、続けてもう一箇所クリックして終点を指定する。
   → 測線が地図上に線として描画されることを確認する(`data-model.md` の `TransectLine`)。
3. サンプリング間隔(メートル)を入力し、断面図作成を実行する。
   → 10秒以内に距離-標高グラフが表示されることを確認する(SC-001)。
4. 別の2点で測線を引き直す。
   → 断面図が新しい測線の内容に更新されることを確認する。

## シナリオ2: 複数時期DEMの比較(User Story 2, FR-014)

1. `demDatasets` に複数(例: 3件)のDEM設定がある状態でシナリオ1を実施する。
2. → 断面図上に、時期ごとに色分けされた複数の線と、対応する凡例が表示されることを確認する。
3. 凡例の項目をクリックし、特定時期の線を非表示にする。
   → その系列のみ非表示になり、他の系列は表示されたままであることを確認する(FR-014)。

## シナリオ3: 断面図のPNGダウンロード(User Story 3)

1. シナリオ1または2で断面図を表示した状態で、断面図のダウンロード操作を行う。
2. → PNGファイルがダウンロードされ、画像ビューアで開くと画面表示と一致する内容(軸・凡例含む)で
   あることを確認する(SC-004)。

## シナリオ4: 測線オーバーレイ地図のPNGダウンロード(User Story 4)

1. 測線が地図上に描画された状態で、地図のダウンロード操作を行う。
2. → PNGファイルがダウンロードされ、測線と縮尺(スケールバー)が画像内に含まれていることを
   確認する(FR-010, FR-011)。
3. タイル配信元がCORSを許可していない設定で試した場合、エラーまたは取得失敗が明示されることを
   確認する(research.md R5のリスク対応)。

## シナリオ5: 異常系(Edge Cases)

- 始点と終点に同一地点を指定 → エラーメッセージが表示され断面図が生成されないことを確認する。
- 測線をDEMデータ範囲外にはみ出させる → 断面図上でその区間がデータ欠損として明示されることを
  確認する(FR-012)。
- 無効なタイルアドレスを設定した状態でアプリを起動 → 地図の該当領域が空白/フォールバック表示に
  なるが、断面図生成機能自体は利用できることを確認する。

## 自動テストの実行

```bash
npm run test
```

`contracts/core-geo-api.md` に定義された関数契約(座標変換・サンプリング・DEM取得・断面図生成)に
対するユニットテストがすべて成功することを確認する(憲法 原則V)。

## ビルド・デプロイ確認

```bash
npm run build
```

`dist/` に静的ファイル一式が生成され、追加のサーバープロセスなしにそのまま配信できることを
確認する(憲法 原則I)。
